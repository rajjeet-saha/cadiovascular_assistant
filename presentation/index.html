The Problem

Wearable heart data is noisy, personal, and ignored

Naive monitors compare every sample to one fixed threshold. On a real wrist that fails three ways — and the failure compounds into alert fatigue: responders learn to ignore the very channel meant to save them.

🏃

Motion lies

Running for a bus elevates heart rate and wrecks PPG signals. A threshold system cries HIGH HEART RATE at perfectly healthy exertion.

📉

One number fits nobody

Athlete resting HR 45. Population threshold: 50. False alarm. A deconditioned patient at “normal” 98? Missed. Fixed thresholds fit no individual.

🔕

Alerts are broadcasts

Existing systems shout once into the void — no persistence check, no patient response loop, no escalation if nobody answers. Silence is not a signal.

The value of an alert channel is inversely proportional to its false-positive rate.

The Idea

Three tiers, one contract

Each layer speaks a fixed, versioned JSON contract — so the simulated wristband can later be replaced by a real ESP32 + sensors with zero software redesign.

WEARABLE · Mobile tierMAX30102 · AD8232 · MPU6050 → ESP32 → BLE → Patient App
CLOUD tier — Express + FirestoreREST API · rule-based alert engine · thresholds · evidence store
CLINICAL tier — Doctor Dashboardlive vitals · ECG · alerts + acknowledge · history · SOS
⌚ BLE transport 🔒 Backend is the only Firestore client 🧩 11 REST endpoints · contract-locked field names

Beyond the Prototype

The escalation engine — our patent direction

Alerts must earn human attention. Our disclosed architecture fuses six signals — measurement, activity context, personal baseline, signal quality, persistence, patient response — into one deterministic escalation machine.

NORMALpersonal baseline
VERIFYINGpersistence window
PATIENT CHECKtap if OK · timeout
ESCALATEDcaregiver → clinician
RECOVERYtightened re-check
EMERGENCYdispatch + location

EVIDENCE BUNDLE · every transition logged

Activity-gated envelopes (running ≠ resting), a post-exertion recovery rule, offline degraded mode — every event fully auditable. Draft filing: docs/patent-proposal.md.
